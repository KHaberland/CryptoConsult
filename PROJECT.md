# MVP Крипто-Консультант: Долгосрочная стратегия с управляемым риском

## 1️⃣ Общая концепция

### Целевая аудитория

Стратегия рассчитана на:

- **Долгосрочных инвесторов (ходлеров)**, которые хотят сохранять капитал и получать умеренный доход, а не торговать активно
- **Инвесторов с горизонтом 1–7 лет**
- **Людей, которые готовы терпеть контролируемую просадку до 30%**
- **Тех, кто ценит осознанность и контроль**, но не хочет принимать решения каждый день

### Что обещает сервис

| Функция | Описание |
|---------|----------|
| Долгосрочная доходность | От +10% до +50% за 3 года (на основе исторических данных), в зависимости от рыночных циклов |
| Защита капитала | Сервис подсказывает защитные действия при превышении допустимой просадки |
| Контроль прогресса | Показывает текущую стоимость портфеля, распределение активов и горизонты инвестирования |

### Что сервис НЕ делает

- ❌ Не управляет активами автоматически
- ❌ Не торгует на бирже
- ❌ Не обещает доход «сегодня или завтра»

## 2️⃣ Вопросы инвестора (анкета)

### Вопрос 1 — Горизонт инвестирования

> "На какой срок вы готовы инвестировать средства?"

- **Ответ инвестора (ввод):** 1–7 лет
- **Комментарий сервиса:** стратегическая цель — долгосрочное удержание, минимальное вмешательство

---

### Вопрос 2 — Сумма инвестирования

> "Какую сумму вы готовы инвестировать?"

- **Ответ инвестора (ввод суммы):** от $1,000 до $50,000 (например, $10,000)
- **Комментарий сервиса:** минимальная сумма рекомендуется для получения реального эффекта DCA и диверсификации. Если сумма слишком мала (например, $100), сервис предложит увеличить капитал для эффективного инвестирования.

---

### Вопрос 3 — Комфортная просадка

> "Какой уровень краткосрочной просадки вы готовы терпеть, не нервничая?"

- **Пример ответа (ввод клиента):** до 30%
- **Комментарий сервиса:** сервис предупреждает, если просадка превышает допустимый уровень.

**Возможные действия:**
- Продолжить удержание без изменений
- Снизить риск (часть активов в стейблы)

---

### Вопрос 4 — Ликвидность

> "Нужна ли вам возможность быстро вывести часть средств при внезапной необходимости?"

**Варианты:**
- ✅ Да, хочу возможность частичного вывода
- ❌ Нет, могу держать весь портфель без вывода

**Комментарий сервиса:** высокая ликвидность позволяет инвестору быстро адаптироваться к событиям, но может снижать доходность за счёт меньшей экспозиции к активам

---

### Вопрос 5 — Опыт инвестирования в криптоактивы

> "Как бы вы оценили свой опыт?"

**Варианты:**
- 🔵 Новичок, раньше не инвестировал
- 🔵 Немного опыта, пару сделок
- 🔵 Средний опыт, понимание рынка
- 🔵 Продвинутый, делал регулярные инвестиции

**Комментарий:** опыт не обязателен, сервис работает для всех уровней. Для более опытных пользователей даёт более подробные комментарии, для менее опытных — более краткие (например: *"В текущей ситуации на рынке я рекомендую держать"*).

---

### Вопрос 6 — Подход к управлению портфелем

Сервис присылает сигналы о частичном перераспределении (10–20% портфеля) при резких движениях на рынке.

> ⚠️ **Активная торговля не поддерживается**

**Комментарий сервиса:** минимально активная стратегия — на редких событиях сервис рекомендует защитные действия

---

### Вопрос 7 — Вход во времени (DCA)

> "Хотите ли вы распределить инвестиции на несколько частей, чтобы снизить риск плохого входа?"

**Варианты:**
- ✅ Да, разделить на 3–6 частей *(рекомендовано)*
- ❌ Нет, вложить всю сумму сразу

**Комментарий сервиса:** вход частями снижает краткосрочный риск; вход всей суммой увеличивает вероятность краткосрочной просадки

---

### Вопрос 8 — Предложение по активам

> "Хотите ли использовать базовый портфель или добавить свои активы?"

**Базовый портфель:**

| Актив | Доля |
|-------|------|
| BTC | 50% |
| ETH | 25% |
| BNB | 7,5% |
| SOL | 7,5% |
| USDT/USDC | 10% |

**Комментарий сервиса:** можно добавить 1–2 альткойна, но это увеличит количество сигналов перераспределения и волатильность; **мемкойны не рекомендуются. Сервис строит стратегию управления из расчета утвержденного пользователем распределения портфеля**

---

### Вопрос 9 — Уведомления

**Комментарий сервиса (фиксировано):** уведомления будут приходить при:

| Событие | Действие |
|---------|----------|
| 📈 Рост портфеля | Рекомендация докупить или перераспределить активы |
| ⚠️ Риск на рынке | Рекомендация перевести часть портфеля в USDT / стейблы |
когда пользователь обращается к программе (по запросу)


> Уведомления встроены для контроля и защиты капитала — выбирать их нельзя.

---

### Вопрос 10 — Контроль прогресса и дедлайн по прибыли

Сервис отслеживает текущий портфель и горизонты инвестирования, раз в месяц присылает отчет о состоянии портфеля. Начиная со срока 12 месяцев с даты инвестирования сервис присылает вопрос по Вариантам действия с портфелем (указано ниже).

**Пример уведомления:**

```
📊 Статус портфеля

Дата старта:                     25.01.2026
Инвестированная сумма:           $10,000
Горизонт стратегии:              3 года
Текущая стоимость портфеля:      $12,850 (+28,5%)
Дата отчёта:                     25.07.2027

Состав портфеля:
├── BTC:        $6,425
├── ETH:        $3,212
├── BNB:        $964
├── SOL:        $964
└── USDT/USDC:  $1,285
```

**Варианты действий:**

| Действие | Вероятность роста | Вероятность просадки | Риск |
|----------|-------------------|----------------------|------|
| ✅ Продолжить придерживаться стратегии | 60–70% | 30–40% | Средний |
| 🔒 Завершить стратегию и зафиксировать доход | — | — | Минимален (упустить рост: 40–50%) |

## 4️⃣ Описание компонентов

### Frontend (React/Next.js)

- Отображает вопросы, ответы, историю и визуализации портфеля
- Общается с Backend по REST API

### Backend (Django REST API)

- Логика пользователей и портфелей
- Формирование контекста для ИИ
- Обработка DCA, допустимых просадок, дедлайнов
- Отправка задач в Celery

### PostgreSQL

Структурированные данные:
- `users` — пользователи
- `portfolios` — портфели
- `sessions` — сессии
- `messages` — сообщения

### Redis

Быстрый кэш:
- Цены активов
- Вероятности
- Временные ответы ИИ

### Celery + брокер (RabbitMQ/Redis)

Фоновые вычисления:
- Пересчёт вероятностей
- Проверка просадок
- Генерация уведомлений
- Подготовка контекста для ИИ

### AI / LLM API

**Получает:**
- Портфель
- Историю сообщений
- Текущие данные рынка

**Возвращает:**
- Рекомендации
- Пояснения
- Вероятностные оценки

Ответ сохраняется в `messages` и отображается пользователю.

## 5️⃣ Поток данных

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│ Пользователь│ ──▶ │  Frontend   │ ──▶ │   Backend   │ ──▶ │   Celery    │
│ задаёт      │     │             │     │             │     │ (асинхронно)│
│ вопрос      │     │             │     │             │     │             │
└─────────────┘     └─────────────┘     └─────────────┘     └──────┬──────┘
                                                                   │
                                                                   ▼
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│ Пользователь│ ◀── │  Frontend   │ ◀── │ PostgreSQL  │ ◀── │   AI / LLM  │
│ видит ответ │     │ отображает  │     │ сохраняет   │     │ формирует   │
│             │     │             │     │ ответ       │     │ ответ       │
└─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
```

### Особенности потока

1. **Пользователь задаёт вопрос** → фронтенд → бэкенд → Celery (асинхронно) → ИИ
2. **ИИ формирует ответ** → сохраняется в PostgreSQL → фронтенд отображает пользователю
3. **Redis** ускоряет повторные запросы и хранит промежуточные расчёты
4. **Celery** проверяет правила стратегии, допустимые просадки и дедлайны → создаёт уведомления
